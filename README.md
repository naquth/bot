# Utas

Aplikasi microblogging full-stack — nulis, balas, suka, simpan, ulang unggah, ikuti, dan dapat notifikasi. Dibangun dengan Next.js 16 (App Router), Supabase (Auth + Postgres + Storage), dan Tailwind CSS v4.

## Fitur

- **Autentikasi**: email/password, Google OAuth, logout, hapus akun permanen (dengan konfirmasi ketik ulang), unduh data pribadi (profil, utas, suka, bookmark, follow — dalam format JSON)
- **Menulis**: post hingga 500 karakter, lampirkan gambar **atau video** (maks 80MB, 3 menit — saling eksklusif dengan gambar), buat poll (2-4 opsi, durasi 1 jam s/d 1 minggu), edit post (dengan label "diedit"), rate limit 8 post/5 menit (ditegakkan di database)
- **Privasi postingan**: tiap post bisa diset "Semua orang" (publik), "Pengikut" (cuma follower penulis yang bisa lihat), atau "Hanya saya" (privat, cuma penulis sendiri). Dipilih lewat tombol chip di composer (`components/visibility-picker.tsx`), ditegakkan penuh lewat RLS di database (bukan cuma filter di kode aplikasi) — lihat `supabase/migrations/add-post-visibility.sql`. Balasan ke post privat/followers-only ikut terlindungi: siapa pun yang tidak berhak melihat post induknya juga tidak akan bisa melihat balasannya, dicek lewat fungsi `can_view_post_thread` yang menelusuri seluruh rantai induk (maks 50 level). Post non-public ditandai ikon kecil di sebelah waktu posting (`components/visibility-badge.tsx`). Bisa diubah kapan saja lewat action `updatePostVisibility`.
- **Draft postingan (`/tulis/draft`)**: composer auto-save ke draft privat setelah jeda mengetik ~1.5 detik (indikator status di header), atau simpan manual lewat tombol "Simpan sebagai draft". Draft menyimpan teks, gambar/video, dan poll — bisa dilanjutkan kapan saja lewat daftar draft, dan otomatis terhapus begitu berhasil dipublikasikan. Disimpan di tabel `post_drafts` terpisah dari `posts` (bukan cuma flag), dengan RLS privat sendiri — supaya draft benar-benar tidak bisa dibaca siapa pun selain pemiliknya, beda dengan tabel `posts` yang memang publik.
- **Telepon & Video Call (di DM)**: panggilan suara/video 1-ke-1 langsung dari halaman chat lewat WebRTC peer-to-peer — layar dering masuk/keluar, kontrol bisukan mikrofon & matikan kamera, tampilan picture-in-picture untuk video lokal. Sinyal panggilan (offer/answer/ICE candidate) dikirim lewat Supabase Realtime Broadcast di channel privat per-percakapan (`calls:<conversation_id>`), diproteksi Realtime Authorization RLS supaya cuma partisipan percakapan itu yang bisa join. **Keterbatasan penting**: koneksi hanya pakai STUN publik gratis (Google), cukup untuk kebanyakan jaringan rumah/kantor biasa, tapi *tidak* dijamin tembus di jaringan dengan NAT simetris atau firewall korporat ketat — untuk keandalan produksi penuh perlu tambahan TURN server relay berbayar (mis. Twilio, Cloudflare Calls, metered.ca). Belum mendukung panggilan grup, cuma DM 1-ke-1.
- **Reels (`/reels`)**: halaman video vertikal full-screen dengan scroll-snap, autoplay otomatis saat video terlihat di layar, tap untuk pause/play, kontrol suara, aksi suka/balas/simpan/bagikan di sisi kanan — dengan bahasa desain Utas sendiri (bukan replika visual Instagram)
- **Poll interaktif**: vote real-time, hasil dalam persen dengan progress bar, tidak bisa vote dua kali (constraint database), otomatis terkunci setelah waktu habis
- **Sematkan (Pin) utas**: satu utas bisa disematkan di paling atas profil (constraint unique di database — cuma boleh 1 pin per akun)
- **Jumlah dilihat**: setiap utas menghitung berapa kali dibuka (ditampilkan di halaman detail)
- **Interaksi**: suka (dengan halaman "disukai oleh"), balas berjenjang, simpan/bookmark, ulang unggah relasional (quote-post) dengan card tertaut ke post asli, salin tautan, auto-link URL
- **@mention**: sebut pengguna lain dengan `@username` — otomatis jadi link, dan yang disebut dapat notifikasi
- **#hashtag**: tulis `#topik` — otomatis jadi link ke halaman `/tag/topik` berisi semua utas dengan tag itu
- **Feed dua tab**: "Untukmu" (semua utas terbaru) dan "Mengikuti" (khusus dari akun yang di-follow)
- **Bisukan (Mute)**: sembunyikan utas seseorang dari feed tanpa unfollow dan tanpa mereka tahu — beda dengan block, tetap bisa saling lihat profil dan DM
- **Laporkan (Report)**: laporkan utas atau akun dengan kategori alasan (spam, pelecehan, ujaran kebencian, dll)
- **Panel Admin** (`/admin`): tindak lanjuti laporan — lihat detail, hapus utas yang dilaporkan, tandai selesai atau tolak, dengan tab Menunggu/Ditindak/Ditolak
- **Verified badge**: centang biru di sebelah nama, diberikan admin lewat menu opsi profil
- **Blokir (Block)**: blokir pengguna — otomatis saling unfollow, profil dan utasnya tersembunyi dari kedua sisi
- **Pesan langsung (DM)**: percakapan 1-ke-1 real-time, bubble chat, kirim gambar di chat, badge pesan belum dibaca di header
- **Grup chat**: percakapan multi-anggota (hingga 100 orang) di `/pesan/grup-baru` — pilih anggota lewat pencarian, beri nama grup, lalu chat bersama. Bubble pesan orang lain menampilkan nama & avatar pengirim (gaya WhatsApp/Telegram). Halaman **Info Grup** (`/pesan/[id]/info`) untuk admin: ganti nama, ganti foto grup, tambah/keluarkan anggota; semua anggota bisa keluar dari grup kapan saja. Keanggotaan disimpan di tabel `conversation_participants` (many-to-many), terpisah dari kolom `user_a`/`user_b` lama yang tetap dipertahankan untuk DM demi kompatibilitas mundur.
- **Voice note di DM**: rekam pesan suara langsung dari browser (MediaRecorder API), pratinjau sebelum kirim, bubble pemutar dengan animasi waveform, disimpan di bucket storage privat (bukan publik) — hanya pengirim & lawan bicara di percakapan yang sama yang bisa memutarnya lewat signed URL. Constraint audio eksplisit (`echoCancellation`, `noiseSuppression`, `autoGainControl` semuanya diset `true`) dan bitrate 128kbps ditetapkan eksplisit di `getUserMedia`/`MediaRecorder`, supaya volume rekaman konsisten across device — sebelumnya `{ audio: true }` polos membuat browser menerapkan default gain control yang tidak konsisten, kadang memotong volume drastis. Ada jaring pengaman timeout 1.2 detik kalau `MediaRecorder.onstop` tidak terpicu (terdokumentasi tidak reliable ~40% acak di Safari/iOS), supaya tombol kirim tidak pernah diam tanpa penjelasan — lihat catatan teknis di bawah.
- **Pencarian dua-mode**: tab Akun dan Utas — bisa cari isi konten post, bukan cuma nama pengguna
- **Jelajahi**: halaman default pencarian menampilkan utas populer 7 hari terakhir
- **Feed infinite scroll**: cursor-based pagination
- **Profil**: edit nama/bio/foto (resize + validasi tipe file di client), logout, tombol kirim pesan
- **Follow**: ikuti/berhenti ikuti, label tombol dinamis
- **Notifikasi**: like, reply, follow, mention, quote — trigger database, badge unread di nav yang akurat di semua sub-halaman
- **Tersimpan**: daftar utas yang dibookmark
- **Hapus post**: dengan dialog konfirmasi
- **Stories**: foto/video sementara yang hilang otomatis setelah 24 jam — tray avatar dengan cincin gradien di atas feed (gaya Instagram/WhatsApp Status), viewer full-screen dengan progress bar per-story, auto-advance, navigasi tap kiri/kanan, jeda tekan-tahan, keterangan singkat, serta daftar "dilihat oleh" khusus pemilik story
- Skeleton loading kontekstual, 404 kustom, error boundary
- Row Level Security + rate limiting di level database
- **Fitur AI** (opsional, jalan tanpa key sekalipun — cuma UI-nya tidak aktif):
  - **Asisten AI (`/asisten`)**: chatbot full-screen, bisa dipakai untuk brainstorming ide post atau ngobrol bebas, akses lewat ikon ✨ di header beranda
  - **Bantuan caption AI**: tombol ✨ di composer (baik quick-composer maupun halaman tulis penuh) — masukkan topik/draf kasar, pilih nada (santai/profesional/lucu/menarik), dapat 3 alternatif caption siap pakai
  - **Ringkasan balasan (TL;DR)**: tombol di halaman detail utas yang punya balasan, merangkum inti diskusi jadi 2-4 kalimat
  - **Deteksi konten AI untuk moderasi**: di panel Admin, tombol "Cek dengan AI" di tiap laporan yang menyertakan post — memberi rekomendasi kategori (spam/pelecehan/ujaran kebencian/kekerasan/aman) sebagai bantuan, keputusan akhir tetap di tangan admin

## ⚠️ Aturan wajib saat menambah query baru (baca sebelum edit `lib/queries/posts.ts`)

Bug "post tidak muncul" pernah terjadi **dua kali** karena alasan yang sama: query `select()` dengan nested join gagal secara diam-diam di Supabase production, padahal `npm run build` tetap sukses (build hanya mengecek TypeScript, tidak pernah menyentuh database sungguhan).

**Penyebab #1** — join ke tabel dengan RLS ketat (`bookmarks`, RLS: `auth.uid() = user_id`) di-join langsung ke query feed yang mencakup baris milik banyak user sekaligus. RLS memblokir baris yang bukan milik user aktif, dan itu bisa membuat **baris post ikut hilang**, bukan cuma kolom join-nya.

**Penyebab #2** — nested self-referencing join (`posts.quote_post_id → posts`) memakai constraint FK yang sama (`posts_author_id_fkey`) dua kali dalam satu query (untuk author post utama, dan untuk author dari quoted-post). PostgREST bisa gagal membedakan konteks ini.

**Aturan tetap:**
1. Jangan join tabel yang RLS-nya membatasi ke `auth.uid()` (bookmarks, dsb) langsung ke query yang mengambil banyak baris milik banyak user. Ambil relasi itu **lewat query terpisah** di `hydratePosts()`, filter manual pakai `.in("id", ids)`.
2. Jangan buat nested join yang memakai nama constraint FK yang sama lebih dari sekali dalam satu query `.select()`. Kalau butuh data dari tabel yang sama (self-join, seperti quoted-post), ambil **lewat query kedua** setelah query utama, lalu gabungkan manual di JavaScript.
3. **Selalu cek `error` dari setiap panggilan Supabase** dan `console.error` dengan detail (`error.message`, `error.details`, `error.hint`) — jangan biarkan error tertelan jadi array kosong tanpa jejak.
4. Setelah mengubah query manapun di `lib/queries/posts.ts`, jalankan `npm run healthcheck` (butuh `.env.local` terisi kredensial Supabase asli) sebelum deploy. Ini memverifikasi query benar-benar berhasil terhadap database sungguhan, bukan cuma lolos TypeScript.
5. Kalau `getFeedPosts` (atau fungsi sejenis) gagal total, jangan diam-diam tampilkan UI "belum ada apa-apa" — itu menyesatkan, seolah datanya memang kosong. Tampilkan pesan error yang jelas (lihat pola di `app/page.tsx`).

## Mengangkat admin pertama

Tidak ada tombol di aplikasi untuk menjadikan seseorang admin — ini disengaja untuk mencegah privilege escalation. Untuk mengangkat admin pertama kali, jalankan manual di Supabase SQL Editor:

```sql
update profiles set is_admin = true where username = 'username_kamu';
```

Setelah punya admin pertama, admin bisa memverifikasi akun lewat menu opsi di halaman profil siapa pun, dan meninjau laporan lewat `/admin` (link muncul otomatis di halaman Pengaturan untuk akun admin).

## Setup lokal

1. Buat project di [supabase.com](https://supabase.com).
2. Jalankan seluruh isi `supabase/schema.sql` di SQL Editor.
3. Aktifkan provider **Email** dan **Google** di Authentication.
4. Salin `.env.local.example` → `.env.local`, isi kredensial.
5. `npm install && npm run dev`

## Deploy ke Vercel

1. Push ke GitHub → import di [vercel.com/new](https://vercel.com/new).
2. Set `NEXT_PUBLIC_SUPABASE_URL` dan `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
3. Tambahkan domain Vercel ke Redirect URLs di Supabase.
4. Deploy.

## Catatan teknis

- **Konstanta disentralisasi** di `lib/constants.ts` — batas karakter, rate limit, dsb didefinisikan sekali dan dipakai di semua composer serta server action, menghindari drift antar file.
- **`shortTime()`** disentralisasi di `lib/format-time.ts`, sebelumnya terduplikasi dengan implementasi sedikit berbeda di dua tempat.
- **Ulang unggah (repost)** diimplementasikan sebagai post baru berisi kutipan + tautan ke post asli — pendekatan ringan tanpa perlu skema tabel repost terpisah, sambil tetap memberi kredit yang jelas ke penulis asli.
- **Menu opsi post** (⋯) sekarang selalu terlihat (bukan hover-only, yang tidak berfungsi di layar sentuh) dan tersedia untuk semua orang (salin tautan), dengan opsi hapus khusus pemilik.
- **Bottom nav** mendeteksi sub-halaman (mis. `/profil/username` tetap meng-highlight ikon Profil) memakai pencocokan prefix path, bukan exact match.
- Upload avatar divalidasi `file.type` sebelum diproses, mencegah file bukan gambar diproses sebagai gambar.
- **Avatar berwarna konsisten per-user** (`components/avatar.tsx`) — warna dihitung dari hash username, jadi setiap orang punya warna avatar yang khas dan selalu sama di seluruh aplikasi, bukan satu warna teal generik untuk semua orang.
- **Micro-animation**: heart "pop" saat like, composer slide-down saat expand, toast slide-up untuk feedback aksi (salin tautan, hapus, repost) — semua menghormati `prefers-reduced-motion`.
- **Skeleton loading pakai shimmer bergerak** (gradient animasi), bukan `animate-pulse` statis — terasa lebih hidup saat memuat.
- **Toast notification global** (`components/toast.tsx`) menggantikan indikator kecil yang gampang terlewat — dipakai untuk konfirmasi salin tautan, hapus post, dan repost.
- Empty state di feed, tersimpan, dan aktivitas kini punya ikon visual, tidak lagi cuma teks kosong.
- **Pesan langsung (DM)** memakai constraint `user_a < user_b` di tabel `conversations` untuk memastikan setiap pasangan pengguna hanya punya satu percakapan (mencegah duplikat A→B dan B→A) — kode aplikasi selalu mengurutkan ID sebelum insert/query untuk menghormati constraint ini. **Grup chat** tidak memakai `user_a`/`user_b` sama sekali (kolom itu dibiarkan `null`); keanggotaan grup maupun DM sekarang sama-sama sumber kebenarannya di tabel `conversation_participants`, supaya satu model query bisa melayani DM lama dan grup baru sekaligus.
- Chat pakai **Supabase Realtime** (`postgres_changes` di tabel `messages`) — pesan baru langsung muncul di kedua sisi tanpa refresh. Tabel `messages` perlu diaktifkan di Realtime publication (`schema.sql` sudah menyertakan `alter publication supabase_realtime add table messages`).
- Pesan ditandai dibaca otomatis saat percakapan dibuka dan saat pesan baru diterima ketika halaman percakapan sedang aktif.
- **Loading state (skeleton) kini menyeluruh** di 10 dari 13 route (2 sisanya — `/masuk` dan `/profil` redirect — sengaja dilewati karena tidak ada fetch data berat sebelum render). Sebelumnya 8 route akan tampil blank sesaat sebelum data server-render selesai, termasuk halaman DM yang paling sering dibuka berulang.
- **RLS `messages` update diperketat** dengan klausa `with check` eksplisit (`sender_id != auth.uid()`) — sebelumnya hanya membatasi baris mana yang bisa diupdate tapi tidak kolom/kondisi apa yang boleh diubah, celah kecil yang bisa dieksploitasi lewat panggilan API langsung di luar aplikasi resmi.
- **Hapus pesan individual** kini bisa dilakukan (klik bubble pesan sendiri → konfirmasi → hapus), dengan sinkronisasi realtime `DELETE` ke kedua sisi percakapan. Tabel `messages` diset `replica identity full` supaya event delete via Supabase Realtime menyertakan data baris lengkap.
- **Realtime menyeluruh** — sebelumnya banyak bagian butuh reload manual untuk melihat perubahan dari user lain. Sekarang:
  - **Feed utama**: post baru dari user lain muncul sebagai banner "N utas baru" yang bisa diklik (pola X/Threads), bukan langsung disisipkan supaya tidak mengganggu posisi scroll.
  - **Detail utas (`/utas/[id]`)**: balasan baru dan perubahan jumlah suka muncul otomatis tanpa refresh, lewat komponen client `ThreadView`.
  - **Notifikasi**: daftar di `/aktivitas` dan badge unread count di navigasi ter-update otomatis saat ada aktivitas baru, tanpa reload.
  - **Pesan (DM)**: daftar percakapan di `/pesan` memperbarui urutan dan preview pesan terakhir secara realtime; badge pesan belum dibaca di header ikut ter-update.
  - **Follower/following count** di halaman profil ter-update otomatis saat ada yang follow/unfollow, termasuk kalau dilihat oleh orang lain secara bersamaan.
  - State unread notification & pesan sekarang dikelola lewat satu **React Context** (`UnreadProvider`) di root layout, jadi konsisten di semua halaman alih-alih setiap halaman fetch sendiri-sendiri.
  - Data pesan pada realtime subscription **tidak pernah membawa isi/konten** pesan orang lain ke client yang tidak berhak — hitungan unread message di-refresh lewat server action yang tetap tunduk pada RLS `conversations`, bukan dibaca langsung dari payload realtime.
- **Upload gambar pada post** disimpan di bucket Supabase Storage `post-images` (path `{user_id}/{timestamp}.jpg`, RLS per-folder seperti avatar). Gambar di-resize dan dikompres di **browser** (canvas, maks 1600px sisi terpanjang, JPEG q0.86) sebelum diunggah, jadi tidak ada beban resize di server. Dimensi asli (`image_width`/`image_height`) disimpan supaya `aspect-ratio` CSS bisa dipasang sebelum gambar selesai dimuat, mencegah layout shift. Klik gambar membuka lightbox full-screen. Post boleh dikirim hanya dengan gambar tanpa teks (pola umum X/Threads).
- **Resize gambar disatukan** di `lib/resize-image.ts` (`resizePostImage` untuk post/chat, `resizeAvatarImage` untuk foto profil) — sebelumnya ada dua implementasi terpisah dan sedikit berbeda antara avatar dan post, sekarang satu sumber logic.
- **Edit post** memakai kolom `edited_at`; label "· diedit" muncul di meta info kalau post pernah diubah. RLS `posts` sekarang punya policy `update` (sebelumnya cuma select/insert/delete).
- **Pencarian konten** (`searchPosts`) memakai `ilike` pada kolom `content`, terpisah dari pencarian akun. Ditampilkan lewat tab di halaman `/cari`.
- **Jelajahi** menghitung skor engagement sederhana di aplikasi (bukan di database) dari post 7 hari terakhir: `suka × 2 + balasan + (ada gambar ? 1 : 0)`. Pendekatan ringan tanpa materialized view atau cron job, cukup untuk skala kecil-menengah.
- **DM dengan gambar** memakai komponen upload ringkas terintegrasi langsung di `ChatThread` (beda dari `ImagePicker` di composer post yang full-width) — preview kecil di atas input, cocok untuk konteks chat yang lebih padat.
- **Quote-post relasional** (`posts.quote_post_id`, FK self-referencing dengan `on delete set null`) menggantikan pendekatan lama yang hanya menyalin teks kutipan lepas. Kalau post asli dihapus, quote tetap ada tapi menampilkan "Utas ini sudah dihapus" alih-alih error atau data kosong.
- **@mention dan #hashtag di-parse otomatis lewat trigger database** (`handle_post_mentions`, `handle_post_hashtags`) saat post dibuat/diedit — bukan di aplikasi. Ini memastikan konsistensi data walau ada insert langsung lewat SQL/admin, dan regex parsing di client (`post-text.tsx`) sengaja disamakan persis dengan regex di database supaya link yang tampil di UI selalu match dengan yang ter-index untuk pencarian.
- **Mention memicu notifikasi** kecuali mention diri sendiri; **quote memicu notifikasi** ke penulis asli kecuali meng-quote post sendiri — pola sama seperti notifikasi like/reply/follow yang sudah ada.
- **`currentUserProfile` untuk `PostCard`** kini diambil otomatis dari `UnreadProvider` (React Context di root layout) lewat hook `useUnread()`, bukan di-pass manual di setiap pemanggilan `PostCard` — ini menghindari perlunya mengubah lima lokasi berbeda (feed, profil, search, thread, tersimpan) saat menambah fitur quote yang butuh data profil user yang login.
- **Blokir memfilter konten di level aplikasi (query JavaScript), bukan lewat RLS** — mengikuti aturan yang didokumentasikan di atas: filter `WHERE author_id NOT IN (...)` aman karena bukan join, sedangkan mengubah RLS `posts`/`profiles` langsung untuk memfilter blokir berisiko menimbulkan bug serupa yang sudah dua kali terjadi. ID user yang diblokir divalidasi format UUID (`UUID_PATTERN`) sebelum dipakai dalam string interpolation query sebagai lapis pertahanan tambahan.
- **Blokir otomatis memutus follow di kedua arah** lewat trigger database (`handle_new_block`) — bukan logic aplikasi — supaya konsisten walau ada insert langsung dari SQL/admin.
- **Laporan (`reports`) tidak bisa dilihat publik**, RLS membatasi hanya pelapor sendiri yang bisa melihat laporannya — data ini sensitif dan tidak untuk konsumsi antar pengguna.
- **Feed "Mengikuti"** mengambil daftar `following_id` dulu lewat query terpisah, baru filter post dengan `.in("author_id", followingIds)` — bukan join langsung, mengikuti pola aman yang sama.
- **Poll** diambil lewat 3 query terpisah berantai (`polls` → `poll_options` → `poll_votes`), digabung manual di `hydratePosts()` — bukan nested join, mengikuti aturan yang sama seperti quoted-post dan bookmark. Satu suara per user ditegakkan lewat composite primary key `(poll_id, voter_id)` di database, bukan cuma validasi di aplikasi.
- **Pin post** ditegakkan maksimal satu per akun lewat **partial unique index** (`posts_pinned_per_author_idx ... where pinned_at is not null`) — constraint di level database, bukan cuma logic aplikasi yang bisa race condition kalau dua request pin bersamaan.
- **Hapus akun** memakai Postgres function `delete_own_account()` dengan `security definer`, dipanggil lewat RPC dari client. Fungsi ini menghapus baris di `auth.users`, yang otomatis mem-cascade hapus semua data terkait (profil, post, pesan, dst) lewat `on delete cascade` di setiap foreign key — tidak perlu menghapus satu-satu secara manual. UI mewajibkan user mengetik ulang kata "HAPUS" sebelum tombol aktif, mencegah penghapusan tidak sengaja.
- **Sistem admin dirancang untuk mencegah privilege escalation** — ini bagian paling sensitif dari update ini:
  - Kolom `is_admin` dan `is_verified` di `profiles` **tidak bisa diubah lewat update biasa oleh user sendiri**, ditegakkan oleh trigger `prevent_self_privilege_escalation` yang membatalkan perubahan kolom itu kalau `auth.uid() = old.id` (update ke baris sendiri).
  - Semua aksi admin (ubah status laporan, hapus post yang dilaporkan, set verified, angkat admin lain) dilakukan lewat **Postgres function `security definer`** yang memvalidasi `is_admin = true` di dalam body function-nya sendiri — bukan cuma mengandalkan RLS. ini dilakukan dengan sengaja supaya validasi keamanannya eksplisit dan mudah diaudit di satu tempat, bukan tersebar implisit antara kombinasi RLS dan trigger.
